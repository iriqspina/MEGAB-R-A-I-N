o que eu entendi, em 30 segundos

O sistema operacional em volta das IAs.

O MEGABRAIN é um protocolo local que organiza como agentes de IA (Claude, Kimi, Gemini, Codex) trabalham nos projetos do : preserva contexto entre sessões, impõe gates de qualidade na entrega, coordena dois agentes no mesmo arquivo sem conflito e transforma erro pago em lição reutilizável.

Não é uma IA nova.É a camada de método, memória e ferramenta em volta das IAs que já existem.
protocolo + skills + scripts
o problema que ele ataca

Agente produz rápido e continua mal.

Cada risco vira uma peça concreta do sistema — não um conselho genérico de "use melhor".

risco · recomeçoMemória

Toda sessão começa lendo ESTADO, HANDOFF, DECISOES e LICOES. O próximo agente não volta ao zero nem repete discussão já decidida.

risco · texto genéricoGates

Toda entrega não-trivial passa por enquadrar, auditar (léxico banido, teste "e daí?"), reparar uma vez e verificar antes de sair.

risco · conflitoTrava

Dois agentes no mesmo projeto se coordenam pelo disco: mb-sync.py lock grava TRAVADO_POR/ATÉ/ESCOPO no HANDOFF e recusa lock concorrente.

SÍNTESEO MEGABRAIN trata IA como força de trabalho que precisa de processo: medir antes de afirmar, registrar antes de encerrar, e deixar o humano aprovar o que é irreversível.
arquitetura · duas camadas + distribuição

Macro no projeto, micro na entrega.

A fusão de 260810 juntou dois mundos: o PIPELINE.md v2 (fases de projeto inteiro) e o protocolo multi-agente (gates de uma entrega). Hoje eles vivem separados de propósito: MEGABRAIN.md cuida do projeto; SKILL.md cuida da entrega.

Um manda na fase.O outro manda na peça. Nenhum dos dois é editado na cópia.
as peças

Quatro camadas, cada uma contra um tipo de falha.

Processo, instrução, memória e garantia separados — uma conversa não carrega o projeto inteiro.

01 · MACRO

Fases do projeto

estado → grelhar → spec → tickets → implementar → validar → publicar → registrar. Vive em MEGABRAIN.md.

02 · MICRO

Gates da entrega

assumir → enquadrar → auditar → reparar → verificar → bastão → registrar. Vive em skills/megabrain/SKILL.md e no plugin.

03 · MEMÓRIA

Quatro registros

ESTADO (onde estamos), HANDOFF (próximo passo), DECISOES (o que perdeu e por quê), LICOES (gatilho/lição/atalho).

04 · GARANTIA

Scripts, não promessas

Regra de ouro 21: o que precisa acontecer sempre vive em bin/ — sync, trava, backup, relatórios, testes — nunca só numa skill.

distribuição

Uma fonte, quatro destinos.

A central em (dois espaços antes do N) é a única que se edita. Tudo mais é cópia propagada por script.

Para dentro dos projetos

  • mb-check-version.py copia a central para o MEGABRAIN/ de cada projeto (Curriculo, Rodada, Portfolio...)
  • Cópia funciona offline; nunca se edita — a fonte manda
  • 260810_sincronizar-identidade.cmd propaga o perfil do usuário para Claude, Gemini, Kimi, Codex

Para fora (público e plugin)

  • mb-generate-template.py gera 260810_github-export/ sanitizado (zero dado pessoal)
  • Export vira _github-repo-local/ (git) e sobe pro GitHub só com autorização
  • plugin-megabrain/ é a fonte do plugin managed do Kimi (hooks + skills)
como opera no dia a dia

Ciclo fechado: assume, entrega, registra.

O agente não começa produzindo: começa lendo. Não termina na entrega: termina no registro. Entre os dois pontos, a entrega passa por gates que só existem se o texto mudou de verdade.

Precedência explícitaFormato que o usuário pediu vence o protocolo; o protocolo governa o conteúdo dentro do formato.
os gates de entrega

Oito passos, dois impossíveis de pular.

Auditar e passar o bastão separam uma primeira passada de uma entrega que atravessa sessões.

00

Assumir

git pull, ler ESTADO → HANDOFF → DECISOES → LICOES, checar trava e versão da central.

01

Enquadrar

Artefato, leitor, decisão que ele toma, 3 critérios verificáveis. Nomear a versão genérica e evitá-la.

02

Gerar

Contexto é orçamento: grep antes de read, checkpoint em arquivo, subagente para trabalho barulhento.

03 · GATE

Auditar + Reparar

Léxico banido, estrutura clichê, teste "e daí?", compressão de 30%. Uma rodada de reparo só.

04 · GATE

Verificar

Números recalculados, datas contra hoje, links abrem, arquivo abre no app de destino.

05 · BASTÃO

Passar

Reescrever ESTADO e HANDOFF, anexar decisões com a alternativa descartada, commitar e empurrar.

06

Registrar

Lição nova entra no arquivo sem pedir permissão. Lição 3× vira regra, skill ou script.

07

Evoluir

Editou a fonte → bump em VERSAO.txt → sincronizar-pipeline.cmd espalha para as cópias.

regras que mais pesam

Quatro das 22 regras de ouro.

As que mais mudam comportamento de agente no dia a dia, das 22 listadas no MEGABRAIN.md.

Medir > supor (9)

Sinal que não se mediu vira ?, nunca chute. Hash e byte em vez de "deve estar igual".

Gerado nunca se edita (4)

Edita-se a fonte ou o gerador e roda de novo. RELATORIO.html e cópias de projeto não se tocam na mão.

Garantia real é script (21)

O que precisa acontecer sempre vive em .cmd/script/hook — nunca só em markdown ou skill.

Local-first (8)

Dado pessoal não sobe pra serviço externo; o pacote público nasce sanitizado por varredura automática.

MULTI-AGENTEClaude e Kimi dividem o mesmo disco: output do outro agente é rascunho, não verdade — audita-se antes de construir em cima. A trava do mb-sync.py impede escrita concorrente no mesmo escopo.
