# Galerias de referência: como ancorar direção visual

Complementa `260810_design-projects.md` (Estágios 1 e 3) e a regra "referência
antes de adjetivo" do anti-slop visual.

## Por que galeria, não adjetivo

"Moderno", "clean", "premium" não restringem nada — cada pessoa lê um layout
diferente atrás da palavra. Uma URL concreta restringe: dá pra apontar o
mecanismo exato (hierarquia, ritmo, contraste) e discordar dele com precisão.

## Regras de uso

- Vá com a pergunta escrita ("como X trata hierarquia de preço?"), não "me
  inspira" — pergunta vaga devolve resposta vaga.
- 2–3 referências, não 20. Board de vinte é indecisão organizada em grade.
- Nomeie a **anti-referência** junto — o que se evita restringe mais que o
  que se busca.
- Extraia o **mecanismo** (por que aquela hierarquia funciona) e descarte a
  forma. Copiar composição é slop com endereço melhor.
- Use nas fases divergentes (Pesquisa, Ideação). Referência durante a
  convergência reabre o que já fechou.

## Como montar a própria biblioteca por sintoma

Organize por **pergunta que a galeria responde**, não por categoria de
mercado — uma galeria de "sites bonitos" não ajuda quando o problema é "como
tratar um formulário de erro". Estrutura sugerida:

| Sintoma / pergunta | Tipo de galeria a buscar |
|---|---|
| "Preciso de volume, várias soluções pro mesmo problema" | Diretório de varredura ampla (curadoria mínima, muito volume) |
| "Preciso do teto de ambição do estilo" | Diretório de prêmios/curadoria seca (enviesa para espetáculo — ruim para ferramenta de trabalho) |
| "É construível? Como fazem essa técnica em código" | Diretório com código aberto / write-ups técnicos |
| "Como um produto real trata Operate/Read (dashboard, docs)?" | Diretório de screenshots de produto real, não de landing pages |
| "Como se comporta estado, feedback, HUD?" | Referência de UI de jogos — mesmos problemas de um dashboard sem a timidez do SaaS |
| "Preciso de uma seção isolada, não a página inteira" | Diretório de componentes/seções recortadas |
| "Material e atmosfera, não layout" | Portfólio de arte/ilustração — ordenar por comunidade (em alta) ou tendência (já saturou), com desconfiança |

Regra: nomear a referência usada; se nenhuma servir, dizer isso em vez de
inventar adjetivo. Cruzar UI de produto real (lógica de estado) + referência
de material (atmosfera) + galeria de composição web (ritmo) é o que produz
superfície que não parece template.

Estas galerias enviesam para Persuade/Experience (site autoral, lançamento);
para Operate e Read, prefira sempre o produto real que a pessoa já abre todo
dia — o screenshot de UI real bate qualquer galeria curada.
