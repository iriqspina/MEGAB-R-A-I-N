# Vidro claro — modelo padrão megabrain para entrega informacional

**Vigência:** a partir de 260909, por pedido do <USUARIO>.
**Vale para:** todo artefato feito pra ele **olhar ou decidir** que **não** é
Markdown — painel, relatório, dashboard, resumo visual, comparativo, status.
**Não vale para:** documento em `.md`, código, nota de trabalho, log.

Substitui o `260909_glass/` (vidro escuro) como default. O escuro continua
válido quando o assunto pede — leitura noturna, peça de vídeo, tema sombrio.

## Por que existe

Antes, cada entrega visual nascia com paleta e tipografia próprias. O <USUARIO>
tem TDAH: painel que muda de linguagem a cada semana custa releitura toda vez.
Um sistema fixo faz o olho achar a informação no mesmo lugar sempre — o que
muda é o conteúdo, não a gramática.

## Arquivos

| Arquivo | O que é |
|---|---|
| `260909_base.css` | Os tokens e componentes. Cole dentro de `<style>` no topo do HTML. |
| `260909_LEIAME.md` | Este arquivo. |

Exemplos vivos, para copiar a estrutura:
- `00_PARA-VOCE/260909_clickup/260909_painel-clickup.html` — diagnóstico com bloqueio, regras e decisões pendentes
- `00_PARA-VOCE/260909_duna/260909_duna-leitura.html` — série temporal com calendário e capa desenhada

## O sistema

**Cor.** Fundo `#F0F0F4` com três manchas de gradiente fixas ao viewport — é
delas que o vidro tira o que borrar. Superfície `rgba(255,255,255,.66)` com
`backdrop-filter: blur(28px) saturate(180%)`. Accent `#0A6BFF`. Semânticos
separados do accent: verde `#22B14C` bom, cinza `#8A8A93` neutro, índigo
`#5A56E0` indefinido, âmbar `#E58A00` pendente, vermelho `#E0332B` bloqueio.
Tema escuro completo nos mesmos tokens — os três estados (claro, escuro,
sistema) estão resolvidos no CSS, não mexa.

**Tipografia.** Instrument Sans nos títulos (600, `letter-spacing` negativo),
Figtree no corpo, JetBrains Mono em **todo número** com `tabular-nums`. Número
fora do mono é bug: as colunas desalinham.

**Layout.** Coluna de 1180px, pilha vertical com `gap:26px`, cada bloco é um
`.glass`. Nada de sidebar.

## Blocos, e quando usar cada um

| Bloco | Classe | Quando |
|---|---|---|
| Barra de progresso | `.progress` + `.steps` | Trabalho em andamento. Marca cada etapa `done`/`now`/`block`/`wait`. |
| Abertura | `.top` / `.hero` | Sempre. Uma frase-tese com o número que importa, não "Relatório de X". |
| Medidas | `.tiles` | 4 números no máximo. Cada um com rótulo e uma linha de contexto. |
| Alerta | `.alert` | Só quando algo está travado. Diz o que travou, por quê, e o que sobrevive. |
| Seção | `section.glass` + `.sec-head` | O corpo. Título curto + uma linha cinza explicando. |
| Cartões | `.rules` / `.dest` | Coisas comparáveis lado a lado. |
| Linhas | `.mline` / `.lrow` | Ranking ou proporção. Barra + valor à direita. |
| Decisões | `.drow` | O que espera resposta dele. Quantidade grande à esquerda, dica à direita. |

## Regras que não se negociam

1. **Toda entrega em `00_PARA-VOCE/<data>_<assunto>/`**, e o caminho completo
   da pasta vai na resposta do chat — nunca só o nome do arquivo.
2. **A primeira frase do topo é a conclusão**, com número. "905 tarefas do ano
   esperavam um clique seu", não "Análise do workspace".
3. **O vocabulário dele é preservado literal.** Se o status no ClickUp é
   `emburreci fml`, o painel escreve `emburreci fml`. Não traduza, não limpe.
4. **Nenhum número sem fonte.** Estimativa vai marcada `[ESTIMATIVA]`.
5. **O que está bloqueado aparece em vermelho e diz o que sobrevive** ao
   bloqueio — nunca esconder a trava no rodapé.
6. **Publicar como Artifact** e entregar o link junto do caminho local.
7. **Uma fonte, N vistas.** O painel lê um `.json` gerado por script; nunca
   números digitados à mão dentro do HTML. Trocar o dado tem que ser regerar,
   não editar markup.
8. **Sem `emoji` como marcador de seção.** Ícone só quando codifica estado.

## Como começar um painel novo

1. Gere a fonte de dados em `.automations/<data>-<assunto>/*.json`.
2. Copie `260909_base.css` para dentro de um `<style>`.
3. Monte os blocos na ordem: progresso (se houver) → abertura → medidas →
   alerta (se houver) → seções → rodapé com o caminho da fonte.
4. Injete os dados por `<script>` a partir do JSON, com um gerador Python —
   não digite os valores no HTML.
5. Abra uma vez no navegador, corrija o que a tela mostrar, publique.
